# ADR 009: Background Jobs Platform Architecture

## Status
Accepted

## Context
Background processing for saved search alerts, digest emails, and analytics telemetry required a resilient background execution architecture decoupled from domain business logic.

## Decision
We established a 4-layer background jobs architecture:
1. `BackgroundJob` Contract: Standardized worker interface specifying `id`, `name`, `intervalMs`, `execute()`, and configurable `retryPolicy`.
2. `JobRegistry`: Centralized registry for discovering and registering workers.
3. `JobDispatcher`: Manages worker execution, state transitions (`Pending`, `Queued`, `Running`, `Succeeded`, `Failed`, `Retrying`, `Disabled`), timeouts, and retry policies.
4. `JobSchedulerService`: Orchestrates timing timers without knowing domain logic, executing registered jobs via `JobDispatcher`.

## Consequences
- Decouples background timing from worker business logic.
- Allows server-side background worker migration in production without modifying worker implementations.
