# ADR 006: Centralized SearchService & Provider Architecture

## Status
Accepted

## Context
Search functionality across Jobs, Companies, Templates, Blog, Resources, and Marketplace required a scalable, unified engine.

## Decision
We established a layered search architecture:
1. `SearchProvider` Interface: Each domain module exposes a normalized `search(query: string)` method returning a standardized `SearchResult` payload.
2. `SearchService`: Central engine aggregating providers, computing multi-stage relevance scores (title, tag, description, freshness), and managing ranking.
3. `SearchController` / `useSearch`: UI hook layer managing debouncing, cancellation, loading states, and search analytics tracking.
4. Separate AI Reranking Layer (`AIReranker`): Optional semantic reranking layer applied downstream of classical search execution.

## Consequences
- Prevents domain knowledge leakage into UI components.
- Ensures classical keyword search remains fully functional if AI services are offline.
